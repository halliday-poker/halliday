# Validation, 3 October 2026

The full repository suite passed **58 tests**, including 15 estimator tests.
After the final estimator metadata/status changes, all 15 estimator tests
were rerun and passed. Existing strategy and equity-engine code is unchanged.

Estimator checks include:

- Reconstruction of pre-action pots, heads-up blinds, seat rotation and current
  boards; malformed, incomplete and duplicate replay rejection.
- Match-ID/timestamp joins and safe feature-cache round trips.
- Parameter recovery from 28,800 synthetic decisions generated by the actual
  `ParamBot` code, including its adaptive mode. Hand-strength outputs were
  injected to exercise every branch; the estimator's probability model was
  not used to generate the labels.
- No-data uncertainty and censored bet-size likelihoods.
- CUDA/CPU likelihood and point-estimate parity, plus failure when CUDA is
  requested but unavailable. CPU is used only in the explicit parity test.
- A planted change recovered with independent held-out confirmation; a constant
  bot left unsplit; global partition cost, tied timestamps, multiple-test
  correction across bots and refusal to extrapolate beyond observed times.

The user dataset was also reconstructed and analyzed end to end:

- Frozen snapshot: **350 matches, 32,158 hands, 203,054 actions, 14 names**.
- No missing hole-card observations or pot/replay validation errors.
- Runtime: Python 3.12.13, PyTorch 2.14.1+cu130, CUDA runtime 13.0, float64.
- Actual device: **NVIDIA GeForce RTX 5070 Ti**; no CPU fallback.
- 2,000 whole-match bootstrap replicates; 9,999 held-out permutations per
  proposed boundary; Holm family-wide alpha 0.05.
- Four boundaries proposed; three confirmed, one rejected; **17 final regimes**.
- Approximately 4.34 seconds for the analysis from the prepared feature cache,
  excluding PyTorch import/startup and initial JSON/replay feature extraction.
  Peak allocated CUDA memory was 571,411,456 bytes (about 545 MiB).

Local output is `analysis/results/opponent-estimates.json` with a Markdown
companion. Full analysis outputs, source logs and the analysis environment are
gitignored. Selected latest-segment profiles are exported separately under
`sparring/competitors/from_data/`. The report contains exact input hashes, settings,
source fingerprint, corrected p-values and all match IDs for reproducibility.

These checks establish implementation behaviour, known-surrogate recovery and
GPU execution. They do not establish that the surrogate family captures every
real bot, guarantee interval coverage after change selection, or prove that a
detected collection-time change was a deployed source-code update. Fifty
matches in this snapshot were seeded from raw/backfilled collection data.
